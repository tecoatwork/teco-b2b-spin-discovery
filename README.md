# SPIN需求澄清：思路与使用方法

Copyright (c) 2026 tecoatwork

## 解决什么问题
用SPIN设计B2B需求澄清问题，结合客户实际回答识别需求、影响与验证步骤。本Skill把分析落实为可验证的问题、客户沟通或具体动作，不以成交保证作为输出。

## 理论是什么
SPIN由Neil Rackham及Huthwaite的销售研究发展而来。S是Situation（现状），P是Problem（问题），I是Implication（影响），N是Need-payoff（解决价值）。它帮助销售把模糊问题转成客户明确表达的需求，不是必须按顺序问完的问卷。

[理论来源](https://www.huthwaiteinternational.com/blog/spin-selling-questions)。以下步骤和案例为外贸场景的原创应用解释，不代表原作者逐字表述。

## 先准备哪些资料
产品与市场；客户类型和联系人职位；客户原话与日期；已知用途和现有方案；当前最想弄清的问题；沟通渠道和语言。

优先提供客户实际原话、发生时间和我方真实条件。公司类型与职位只能支持初步假设；已有客户记录应优先于一般行业印象。可以提供相关笔记路径，读取失败时应说明，不能假装读过。

## 完整分析方法

### 第1步：整理现状

从已有资料提取用途、使用者、采购阶段和现有方案。公开资料可以查到的内容先研究，不重复向客户索要；客户内部情况没有证据就保留未知。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第2步：找到问题

从客户原话找到具体不便、限制或未达目标。把销售自己的推测单列为假设；允许客户回答“没有这个问题”。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第3步：了解影响

问这个问题影响谁、哪个环节、频率如何，以及客户是否认为值得解决。金额、频次和损失由客户或可追溯资料确认，不用夸张损失制造紧迫感。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第4步：确认解决价值

请客户说明解决后最希望改善什么、如何判断有效。没有明确问题时，不强行引导其认可产品价值。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第5步：安排本轮问题

优先选最影响方案的1—3个问题，注明目的与回答后的分支。按客户回复调整顺序；首封邮件不塞入完整SPIN问卷。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

## 外贸演示案例

模拟：客户只说需要Wax Heater目录和报价。先确认使用场景及适配蜡型，不先问“现有设备是不是温控不好”。客户若主动提到清洁麻烦，再问影响哪些使用环节；若没有清洁问题，就不把硅胶碗当作主卖点。

以上是教学模拟，不是已发生的交易、真实客户回答或产品性能证明。实操时用当前客户资料替换，引用来源，不直接复制成事实。

## 最终交付与用途

需求判断摘要；SPIN问题表（类型｜已知依据｜建议问题｜为何现在问｜不同回答后的行动）；本轮可发送问句草稿；需求验证记录。

内部分析用于判断和准备；对客稿用于人工审核后沟通。清单中的负责人、时间及动作如未经双方确认，标注“建议”，不能写成双方约定。客户回复后更新相关判断，不把旧结论长期当作事实。

## 证据如何处理

| 信息状态 | 写法与处理 |
|---|---|
| 客户明确回答 | 保留原话或准确转述、日期与上下文 |
| 我方确认的能力与权限 | 标注资料版本或授权来源，不扩大适用范围 |
| 公开资料 | 链接、发布日期或查询日期；企业自述仍标注自述 |
| 分析假设 | 说明依据、替代解释及验证问题 |
| 缺少资料 | 写待确认，并指出缺口是否影响当前行动 |

## 如何与已有工作流配合

把客户确认的需求交给FABMP做价值表达，再交给询盘回复Skill。需要判断内部决策流程时使用MEDDPICC。

这些衔接是使用建议，不要求安装其他Skill才能运行。避免重复调研；把已确认资料、未决问题、来源和下一步一起交接即可。

## 可直接借鉴的沟通问题

根据客户已提供的信息选择使用，不要一次问完。涉及我方方案变化的表达只有在实际可执行时才能使用。

| 目的 | 示例表达 |
|---|---|
| 现状 | 这款设备主要用于门店服务，还是零售给消费者？ |
| 问题 | 目前的设备有没有让你们觉得不方便的地方？ |
| 影响 | 这个问题主要影响使用体验，还是增加了售后工作？ |
| 解决价值 | 如果改善这一点，你们会用什么标准判断新方案值得采用？ |

## 常见误区

把询盘少当成客户没有需求；连续盘问；把假设写成客户痛点；用引导性问题诱导同意；忽略客户已明确提出的价格或目录请求。

## 如何判断结果是否可用

- 判断能否追溯到资料，假设是否明确标注？
- 是否选出了当前最重要的缺口，而非堆砌所有可能问题？
- 对客表达是否自然，并且只有一个清晰的本轮下一步？
- 是否超出了我方能力、授权或客户联系约定？
- 一线销售能否看完就知道该问谁、准备什么、做什么？

## 边界场景自检

输入只有“多少钱”：先回答可回答部分并澄清关键规格，不捏造痛点。客户说没有质量问题：不得继续渲染质量损失。

这些是使用前的人工检查情境，并非已经完成跨模型或真实销售效果测试。

## 启动方式

```text
请使用 $teco-b2b-spin-discovery。你好，请你告诉我，需要提供什么信息给你。
```

也可以直接给资料：

```text
请使用 $teco-b2b-spin-discovery。
客户及场景：[填写]
客户原话与日期：[填写或相关笔记路径]
产品与我方条件：[填写]
本轮目标：[填写]
回复语言：[填写]
请区分事实与假设，给出简洁判断和下一步；仅起草，不发送。
```
